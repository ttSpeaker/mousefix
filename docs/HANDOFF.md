# MouseFix Engineering Handoff & Technical Reference

This document serves as the technical reference, architectural overview, and iteration handoff for engineers and AI agents continuing work on MouseFix.

---

## 1. Project Background & Goals

MouseFix is a clean, modern Swift/SwiftUI reimplementation of the core features of **Mac Mouse Fix**, engineered using reverse-engineering analysis (via Hopper / REA) of `Mac Mouse Fix.app` (v3.1.0).

Primary design objectives:
- **Zero Kernel Extensions:** Pure user-space CoreGraphics event tap architecture.
- **Natural Smooth Scrolling:** Smooth, trackpad-quality inertia scrolling for standard stepped mechanical wheels.
- **Window & Gesture Remapping:** Native macOS desktop space switching (Left/Right Spaces) and Mission Control without third-party drivers.
- **Low Footprint & High Responsiveness:** Minimal CPU/memory overhead, sub-millisecond event classification, and seamless background execution.

## 2. Core Architecture & Reverse-Engineered Findings

### A. The CoreGraphics Event Tap Boundary (`EventTapManager` & `EventTapFilter`)
- **Tap Level:** The event tap must intercept at `CGEventTapLocation.cghidEventTap` with `CGEventTapPlacement.headInsertEventTap` and `CGEventTapOptions.defaultTap`.
- **Events of Interest:**
  - `CGEventType.scrollWheel` (`1 << 22`)
  - `CGEventType.otherMouseDown` (`1 << 25`)
  - `CGEventType.otherMouseUp` (`1 << 26`)
- **Stepped vs. Continuous Scroll Discrimination:**
  Mac Mouse Fix identifies non-trackpad physical mouse wheels by reading:
  - `scrollWheelEventIsContinuous`: Stepped wheels report `0`; Apple Magic Mouse and Trackpads report `1`.
  - `scrollWheelEventMomentumPhase`: Physical mice report `0`.
  - If `isContinuous == 0` and `momentumPhase == 0`, the event is classified as `.interceptScroll(dy, dx)`.
- **Recursion Prevention Guard (`magicUserData`):**
  Synthesized scroll and button events generated by MouseFix are stamped with:
  ```swift
  event.setIntegerValueField(.eventSourceUserData, value: 0x4D4D4658) // "MMFX" in ASCII
  ```
  `EventTapFilter.classify` immediately returns `.passThrough` for any event matching this marker, preventing infinite feedback loops.

### B. Smooth Scrolling Physics & Subpixel Accumulation (`SmoothScrollEngine` & `ScrollEventPoster`)
- Physical mouse wheels emit discrete integer ticks (typically `dy = ±1` or `dy = ±2`).
- Discrete steps are translated into virtual velocity impulses:
  ```
  velocity += impulse * stepSize (e.g. 30px)
  ```
- Physics decay loop runs at 60–120Hz (via `CADisplayLink` or high-resolution `DispatchSourceTimer`):
  ```
  velocity *= friction (e.g. 0.88 - 0.92)
  ```
- **Subpixel Delta Accumulation:**
  macOS continuous scroll events expect pixel deltas in both integer units (`scrollWheelEventDeltaAxis1`) and subpixel float units (`scrollWheelEventPointDeltaAxis1`). Fractional pixels are accumulated in an internal accumulator and flushed when exceeding integer boundaries to ensure silky 120Hz ProMotion scrolling without jitter.
- **Dispatch Route:**
  Continuous trackpad scroll events (`isContinuous = 1`) must be posted directly to **`CGEventTapLocation.cgSessionEventTap`** so that open application windows receive proper trackpad momentum.

### C. macOS Desktop Space & Window Gestures (`SymbolicHotKeys` & `ActionSimulator`)
- **Hopper Reversing Discovery:**
  Direct synthesis of `Ctrl + Arrow` keyboard chords fails to switch spaces or open Mission Control because macOS `WindowServer` treats these system actions as **Symbolic Hotkeys**.
- **Private SkyLight API Resolution:**
  MouseFix dynamically loads `/System/Library/PrivateFrameworks/SkyLight.framework/SkyLight` via `dlopen`/`dlsym`:
  - `CGSSetSymbolicHotKeyEnabled(hotKey: Int32, enabled: Bool) -> Int32`
  - `CGSSetSymbolicHotKeyValue(hotKey: Int32, unichar: UniChar, keyCode: UInt16, modifiers: UInt64) -> Int32`
- **Standard Hotkey IDs:**
  - `79`: Move Left a Space
  - `81`: Move Right a Space
  - `32`: Mission Control
  - `33`: Application Windows (App Exposé)
  - `36`: Show Desktop
- **Posting Protocol:**
  MouseFix dynamically sets the hotkey value to a custom virtual key code `(hotKey + 0x190)` with modifiers `0xa00000` (Control flag), and immediately posts key down and key up events to `kCGSessionEventTap`. `WindowServer` matches the symbolic hotkey and executes the window manager animation instantly.

### D. Button Numbering & Middle-Click Pass-Through
- **CoreGraphics Button Indexing:**
  - Button index `2` = Physical **Button 3** (Middle Click / Scroll Wheel Click)
  - Button index `3` = Physical **Button 4** (Thumb Back / Lower Side Button)
  - Button index `4` = Physical **Button 5** (Thumb Forward / Upper Side Button)
- **Click vs. Hold Discrimination:**
  - Tracked via `ButtonStateMachine`.
  - When a button is pressed down, a timer starts with threshold (default `0.30s`).
  - If held past threshold, `holdAction` triggers (e.g., Mission Control).
  - If released before threshold:
    - If `clickAction != nil`: executes action (e.g., Space switch).
    - If `clickAction == nil`: invokes `ActionSimulator.postRawButtonClick(button:)` to re-synthesize `otherMouseDown` + `otherMouseUp` at the current cursor coordinates. This allows standard browser middle-clicking (opening links in background tabs, closing tabs) to work without interference.

### E. App Lifecycle & Background Execution
- **Window Management (`AppDelegate`):**
  - `applicationShouldTerminateAfterLastWindowClosed` returns `false`.
  - Main window has `isReleasedWhenClosed = false`. Clicking `(X)` hides the window while the daemon engine stays alive.
  - Clicking the Dock icon or choosing **Open Settings...** calls `showSettingsWindow()`, bringing the existing window to the front.
- **Menu Bar Status Item (`NSStatusItem` & `NSMenuDelegate`):**
  - Uses `NSStatusBar.system.statusItem` for universal macOS 12+ compatibility.
  - Conforms `AppDelegate` to `NSMenuDelegate` and implements `menuWillOpen(_:)` to dynamically check `AppState.isAccessibilityGranted` and `LaunchAtLogin.isEnabled` whenever the menu opens, guaranteeing fresh state indicators.

## 3. macOS TCC & Code Signing Specifics

### Ad-Hoc vs. Developer ID Signing
- **Development Builds:**
  `scripts/bundle-app.sh` signs the bundle with ad-hoc identity:
  ```bash
  codesign -f -s - --deep MouseFix.app
  ```
- **TCC Quirk:**
  When an app is signed ad-hoc (`-s -`), macOS TCC identifies the permission grant by the exact cryptographic binary hash (`cdhash`).
  **Consequence:** Every time the binary is recompiled, the hash changes. The toggle in **System Settings → Accessibility** will appear ON, but TCC will reject the new binary until the user toggles it **OFF and back ON** (or resets with `tccutil reset Accessibility com.user.MouseFix`).
- **Production Release:**
  When releasing for general distribution, sign with an **Apple Developer ID Application** certificate and notarize via `xcrun notarytool`:
  ```bash
  codesign --force --options runtime --sign "Developer ID Application: Your Name (TEAMID)" MouseFix.app
  ```
  Developer ID signed apps bind to the stable team/identity certificate instead of `cdhash`, completely eliminating permission drops across app updates.
